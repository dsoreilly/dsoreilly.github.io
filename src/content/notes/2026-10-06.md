## 3

Stacked pull requests is a new (preview) GitHub feature for stacking related pull requests, toted as way to help mitigate some of the human code review burden of AI generated code.

Where I'm currently at with this feature is that Copilot starts each session in a separate worktree. Trying to rebase a stack with the `gh stack` tool is proving troublesome. Seems like this tool was initially built to make AI generated pull requests easier to manage, but using GitHub's AI tool is making this actually more difficult.

**Update**

Okay, so there was an update released ([0.2.0](https://github.com/github/gh-stack/releases/tag/v0.2.0/)) to address this:

> Cross-worktree rebase, sync, and modify: These commands can now operate on a stack whose branches are spread across different worktrees — each change runs in the checkout that holds the branch, so you no longer need to gather the whole stack into one directory.

This tool makes a whole lot more sense now. Given the whole idea around stacked pull requests is to alleviate some of the issues around the onslaught of AI generated PRs, the tool needs to be aligned with the current AI workflow.
